# 下载器迭代计划

创建及最近更新：2026-10-28

状态：第一阶段已完成，后续阶段待实施。本文记录功能建议和推荐顺序，勾选项表示已经实现并通过相应验收；具体版本号与发布时间在发布时确定。当前已实现功能以 [README](../README.md#功能) 为准。

## 当前基础

已有 HTTP/HTTPS 下载、批量添加、并发队列、暂停与断点续传、自动重试、代理、任务持久化、列表与卡片视图、搜索筛选、多选操作和完成通知。

后续优先完善下载控制、任务配置与后台使用体验，再扩展下载引擎。

## 迭代顺序

| 阶段 | 目标 | 主要功能 |
| --- | --- | --- |
| 第一阶段：下一轮迭代 | 更好地控制和查看下载 | 全局限速、高级新建任务、任务详情 |
| 第二阶段 | 适合长期运行和批量任务 | 托盘与后台下载、队列优先级、计划下载 |
| 第三阶段 | 增强可靠性和下载能力 | 单任务限速、文件校验、失效链接更新、多连接分片、浏览器扩展 |
| 按需穿插 | 减少日常重复操作 | 导入导出、分类目录、拖放添加、剪贴板提示、诊断日志 |

## 第一阶段：下载控制与任务配置

### 1. 全局限速

- [x] 支持设置所有任务合计的下载速度上限，并提供不限速选项。
- [x] 下载过程中修改限制能够生效，设置在重启后保留。
- [x] 多任务共享额度，限速等待可取消，暂停与退出能及时响应；主动限速不会被误判为连接停滞。

验收重点：用本地 HTTP 服务器验证多任务合计速度、动态调节和取消行为，允许合理的短时突发与测量误差。

### 2. 高级新建任务

- [x] 在现有快速添加入口之外，提供单任务的保存目录与文件名配置。
- [x] 支持 Referer、Cookie 和自定义请求头，复用现有代理与认证能力。
- [x] 自定义文件名仍遵守最终文件、`.part` 与 `.part.meta` 的冲突预留规则。
- [x] Cookie、Authorization 等敏感字段不写入普通 JSON、复制内容或日志；需要跨重启保存时通过凭据存储处理。
- [x] 下载引擎管理 Range、If-Range 和 Accept-Encoding 等影响续传正确性的字段；自定义请求头不会破坏续传或向无关重定向目标泄露认证信息。

验收重点：本地测试覆盖自定义请求头、认证、重定向、目录不可写和同名文件；原有批量快速添加仍可使用。

### 3. 任务详情

- [x] 集中展示链接、保存路径、文件大小、已下载量、速度、预计剩余时间、创建与完成时间、重试次数和续传能力。
- [x] 提供完整错误说明与复制诊断信息的入口，诊断信息去除凭据。
- [x] 明确未知大小、尚未获取续传能力、文件缺失等状态，避免显示误导性数值。

验收重点：覆盖下载中、排队、暂停、失败、完成和未知长度状态；详情打开时保持更新。速度曲线作为后续增强项。

### 第一阶段实施记录（2026-10-28）

- **入口**：设置 → 常规 → 全局限速；主界面 → 高级新建；任务行、卡片的详情按钮及右键菜单 → 任务详情。
- **限速**：所有任务共享额度，0 表示不限速；动态调整不重新建立连接，短时突发控制在小块读取范围内。
- **高级任务**：文件名与目录可单独指定；同一链接的已停止任务可补填请求头，保留原保存路径和进度。所有自定义请求头仅存内存，首期不提供跨重启的凭据存储；重启后通过同一入口补填。
- **详情**：保留自动重试次数，区分未知和不支持续传；诊断文本去除 URL 认证与查询参数值，错误信息过滤请求凭据。任务时长包含暂停时间，速度曲线仍列在后续增强项中。
- **验证**：在 Windows/amd64 上完成 `CGO_ENABLED=0` 的全量测试与构建、`go tool mygo vet .`，并对下载、应用、设置和存储包执行 race 检查。网络用例使用本地 HTTP 服务，UI 用例覆盖输入、焦点、关闭重开、详情更新和诊断复制。
- **视觉检查**：生成并检查浅色、深色主题的真实像素快照，包含 960×640 最小窗口、125% 缩放下的高级表单及滚动内容、任务详情、错误详情和限速设置；同步更新 README 的两套界面截图。
- **验证范围限制**：未手动验证原生窗口中的文件选择器、系统剪贴板等行为，未在 macOS/Linux 实机运行。

## 第二阶段：后台运行与队列调度

### 4. 托盘与后台下载

- [ ] 提供关闭窗口后进入托盘继续下载的选项，并保留明确的退出入口。
- [ ] 托盘支持恢复窗口、查看下载概况、全部暂停和全部继续。
- [ ] 真正退出时仍正常取消工作任务、保存进度并释放单实例资源。

验收重点：先核实当前 MyGo 与各平台的托盘、窗口隐藏和恢复能力，再分平台实施；在目标系统实测关闭、恢复、退出和通知行为，未支持的平台明确说明。

### 5. 队列优先级

- [ ] 支持将任务置顶、上移和下移，优先启动指定的排队任务。
- [ ] 调度顺序独立于列表的名称、大小和时间排序，并在重启后保留。
- [ ] 首期只调整尚未开始任务的顺序，已运行任务继续下载。

验收重点：验证并发上限、暂停后继续、删除队列项及重启恢复后的启动顺序。

### 6. 计划下载

- [ ] 支持指定开始时间，以及允许下载的每日时间段。
- [ ] 调度与手动暂停、优先级和并发数协调，避免自动恢复用户主动暂停的任务。
- [ ] 持久化计划，并定义错过开始时间、应用重启和系统时间变化后的处理方式。

验收重点：通过可替换的时钟验证时间边界。首期只在应用运行期间调度，不包含唤醒电脑或自动启动应用。

## 第三阶段：可靠性与引擎扩展

### 7. 单任务限速

- [ ] 在全局限速基础上，允许为单个任务设置独立上限。
- [ ] 单任务与全局限制同时生效，运行中修改不会丢失进度。

### 8. 文件完整性校验

- [ ] 允许输入预期 SHA-256，下载后在后台计算并显示匹配或不匹配。
- [ ] 区分下载完成与校验结果；校验可取消，大文件校验不阻塞界面。

### 9. 更新失效链接

- [ ] 为暂停或失败的任务更换过期下载地址，保留原任务记录与目标路径。
- [ ] 只有能够确认新旧文件版本一致时才沿用部分数据；不能确认时重新下载，避免拼接不同内容。

### 10. 多连接分片下载

- [ ] 探测服务器是否支持有效的 Range 响应，不支持时回退到单连接。
- [ ] 实现分片调度、分片进度持久化、暂停恢复、失败重试和完成校验。
- [ ] 各连接验证响应范围、总长度与文件版本，统一遵守限速、代理和取消规则。
- [ ] 定义单任务连接数与全局连接数上限，使用可控的本地服务验证正确性并衡量吞吐收益。

此项需要较多下载引擎改造。多连接不保证提速，效果取决于服务端与网络条件；应在前述基础功能稳定后实施。

### 11. 浏览器扩展接管下载

- [ ] 先确定浏览器扩展与桌面应用之间的通信方式，以及链接、文件名、请求头的传递格式。
- [ ] 首期支持用户主动将链接发送到下载器，再评估自动接管下载。
- [ ] 验证应用未启动、重复链接、认证数据传递和连接失败等情况。

## 可按需穿插的功能

- [ ] **批量导入与导出**：导入 TXT 链接列表，导出不含认证信息的任务清单。
- [ ] **分类与目录规则**：按扩展名或域名分配保存目录，并允许单任务覆盖。
- [ ] **拖放添加**：拖入链接或链接文件创建任务，复用现有解析与去重逻辑。
- [ ] **剪贴板链接提示**：用户主动开启后识别链接并提示添加，避免重复提示。
- [ ] **诊断日志导出**：记录重试、HTTP 状态与代理错误，脱敏认证字段并限制日志大小。
- [ ] **速度曲线**：在任务详情中展示近期速度变化，限制采样数量和内存占用。

## 暂不优先的方向

BT／磁力、HLS 等视频流解析需要引入新的下载引擎或专门的媒体处理流程，维护成本较高，暂列为独立方向，后续有明确需求再评估。

## 实施与验收约定

- 保持现有包边界，UI 与平台服务放在 `internal/app`，下载能力放在 `internal/download`；设置和记录扩展保持旧数据兼容。
- 涉及 UI、窗口行为或 MyGo API 时，先阅读 [MyGo 维护技能](../.agents/skills/mygo-maintenance/SKILL.md)，查阅当前依赖源码；框架能力尚未核实的功能不视为已可用。
- 按 [项目协作规范](../AGENTS.md#验证与测试) 和 [README 验证说明](../README.md#验证与视觉快照) 执行相应测试、静态检查和视觉快照；网络测试使用本地服务。
- 每完成一项，勾选对应任务并同步 README 的功能和限制说明；涉及原生系统能力时，记录实际验证的平台与仍未验证的行为。
